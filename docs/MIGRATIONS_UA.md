# Міграції бази даних

Схема бази змінюється лише через міграції (файли в `api/src/migrations`). Автоматична синхронізація схеми вимкнена,
тож зміна коду сама ніколи не видалить колонку з даними. Міграції застосовуються автоматично при старті API.

## Одноразове налаштування (базова міграція)

    cd ~/server
    ./scripts/migration-baseline.sh
    git add api/src/migrations
    git commit -m "api: baseline migration"
    docker compose up -d --build api

Базова міграція створює всю поточну схему на порожній базі. На базі, де таблиці вже є (як зараз), вона нічого не робить і лише
записується як виконана. Тому та сама міграція працює і на цьому сервері, і на новій машині з порожньою базою.

## Перевірка, що схема збігається з кодом

    ./scripts/schema-check.sh

## Як змінити схему

1. Зробіть резервну копію: `./scripts/backup.sh`
2. Змініть сутність у коді (колонку, таблицю).
3. Згенеруйте міграцію: `./scripts/migration-generate.sh НазваЗміни`
4. Відкрийте новий файл у `api/src/migrations` і прочитайте SQL.
   Перейменування колонки генератор записує як «видалити стару і створити нову», а це втрата даних: у такому разі замініть SQL на `ALTER TABLE ... RENAME COLUMN ...`.
5. Закомітьте файл і перезберіть API: `docker compose up -d --build api`

## Відкат міграції

Кожна міграція має метод `down`, але на практиці надійніше відновити базу з копії (див. `docs/BACKUP_UA.md`) і відкотити код через `git`.
