# Розумна лабораторія: Home Assistant

Застосунок працює з Home Assistant (HA) лише через його REST API і тільки з пристроями, які адмін явно додав у список дозволених.
Браузер ніколи не звертається до HA напряму. Токен HA лежить тільки в `.env` на сервері.
HA не відкривається в інтернет: Funnel веде лише на застосунок (порт 3000).

## У застосунку

- **`/smart` — «Розумна лабораторія»** (пункт меню, кнопка в «Лабораторії»). Плитки за кімнатами:
  - світло: перемикач і повзунок яскравості (запит іде, коли повзунок зупинився, а не на кожен рух);
  - сцени: кнопка «Увімкнути»;
  - датчики: значення з одиницями; датчики «так/ні» — текстом за типом («Є рух», «Сухо», «Зачинено»), тривожні стани червоним.
  - Стан оновлюється раз на 15 секунд. Недоступний пристрій сірий з позначкою «недоступний».
  - Бачать усі; керують світлом і сценами модератори й адмін.
- **`/smart/devices` — «Пристрої»** (лише адмін): стан зв'язку з HA, дозволені пристрої (змінити назву й кімнату, приховати, прибрати),
  знайдені в HA з пошуком і кнопкою «Додати».

## Що вміє API

- `GET /api/smart/entities` (усі): стан дозволених пристроїв.
- `POST /api/smart/lights/:id/state` (admin, moderator): `{ "on": true, "brightness": 1-100 }`.
- `POST /api/smart/scenes/:id/activate` (admin, moderator).
- `GET /api/smart/status`, `GET /api/smart/discover`, `GET/POST/PATCH/DELETE /api/smart/allowlist` (admin): список дозволених.

Дозволені лише чотири типи: `light`, `sensor`, `binary_sensor` (лише перегляд) і `scene`. Розетки, вимикачі й будь-що інше (`switch.*`)
додати неможливо, щоб застосунок не міг дистанційно вмикати паяльники, нагрівачі чи 3D-принтери.
Кожна дія (світло, сцена, зміна списку) пишеться в журнал дій. Запит до HA має ліміт часу 5 секунд,
для дій діє ліміт 30 на хвилину на користувача. Подробиці полів — у `docs/API_UA.md`.

## Налаштування на сервері

1. У HA: профіль користувача (внизу ліворуч) → вкладка Security → Long-lived access tokens → Create token. Скопіюйте токен.
2. Додайте його в `.env` на сервері (без показу на екрані):

       read -s -p "Токен HA: " HAT; echo
       printf 'HA_TOKEN=%s\n' "$HAT" >> ~/server/.env
       unset HAT

3. Перезапустіть API: `cd ~/server && docker compose up -d api`
4. Перевірте зв'язок: у застосунку адміном відкрийте «Розумна лабораторія → Пристрої». Має бути «Зв'язок є» і версія HA.

HA стоїть на тому ж сервері в режимі `network_mode: host`, а API працює в контейнері, тому до HA він звертається за адресою
`http://host.docker.internal:8123` (змінна `HA_URL`, значення за замовчуванням уже таке).

## Тестування без обладнання

У файлі `~/homeassistant/config/configuration.yaml` рядок `demo:` додає вигадані лампи й датчики
(`light.bed_light`, `light.ceiling_lights`, `binary_sensor.basement_floor_wet` та інші). Після перевірки:

1. Приберіть демо-пристрої зі списку на сторінці «Пристрої».
2. Видаліть рядок `demo:` і перезапустіть HA (кнопка в розширеній панелі або `docker restart homeassistant`).

## Додавання пристрою

1. Підключіть пристрій у самому HA.
2. «Розумна лабораторія → Пристрої → Знайдено в Home Assistant» → «Додати», вкажіть назву для застосунку й кімнату.
3. Пристрій одразу з'явиться на сторінці `/smart`.

## Коди помилок

`SMART_NOT_CONFIGURED` (немає токена), `SMART_UNAVAILABLE` (HA не відповідає за 5 с), `SMART_AUTH_FAILED` (HA відхилив токен),
`UNKNOWN_HA_ENTITY`, `ENTITY_KIND_MISMATCH`, `SMART_ENTITY_EXISTS`, `SMART_DEVICE_NOT_FOUND`, `DEVICE_UNAVAILABLE`, `BRIGHTNESS_REQUIRES_ON`.
