# Вебінтерфейс DigiComp HUB

Інтерфейс (`api/web`) роздає сам NestJS: окремий шлюз (Python) більше не потрібен. Один процес, один домен, жодної збірки фронтенду:
файли віддаються як є (ES-модулі, CSS, шрифти).

## Як усе влаштовано

- Вхід через cookie: `POST /auth/login` із заголовком `X-DC-Client: web` ставить два HttpOnly-cookie (`dc_at` на 1 годину, `dc_rt` на 30 днів,
  шлях `/auth`), а тіло відповіді містить лише `user`. Токени ніколи не потрапляють у JavaScript.
- Захист від підробки запитів (CSRF): cookie мають `SameSite=Strict`; усі запити, що змінюють дані, мусять нести заголовок `X-DC-Client: web`,
  а заголовок `Origin` (якщо є) має збігатися з адресою сервера. Інакше відповідь 403 із кодом `CSRF`.
- Звичайні API-клієнти (curl, скрипти) працюють як раніше: токени в тілі відповіді й заголовок `Authorization: Bearer`.
- Політика безпеки вмісту (CSP) забороняє вбудовані скрипти й стилі та зовнішні ресурси; усе завантажується з власного домену.
- Маршрути інтерфейсу використовують `#`-адреси (`/#/places/SOLDER-01`), тому не конфліктують з адресами API.

## Змінні в `.env`

    COOKIE_SECURE=true
    PUBLIC_ORIGIN=https://digicomp.tailfbb38b.ts.net

`COOKIE_SECURE=true` додає прапорець Secure до cookie (потрібно, коли сайт відкривають через https). `PUBLIC_ORIGIN` це адреса, яка потрапляє
в QR-коди місць; без неї береться адреса, з якої відкрито сторінку.

## Поетапний перехід зі старого шлюзу

1. Запустіть оновлений бекенд і перевірте новий інтерфейс приватно, лише для пристроїв вашої мережі Tailscale:

       sudo tailscale serve --bg --https=8443 3000

   Адреса: `https://digicomp.tailfbb38b.ts.net:8443`. Публічний сайт (Funnel на порту 443) при цьому лишається на старому шлюзі.
2. Коли все влаштує, перемкніть публічну адресу на новий інтерфейс і вимкніть старий шлюз:

       sudo tailscale funnel --bg 3000
       sudo systemctl disable --now digicomp-hub

3. Відкат: `sudo tailscale funnel --bg 8765` і `sudo systemctl enable --now digicomp-hub`.

## Для розробників

- `js/app.js`: оболонка, навігація, панель активного сеансу. `js/router.js`: маршрути. `js/api.js`: клієнт із прозорим оновленням сеансу.
- Новий розділ: файл у `js/views/`, рядок `route(...)` в `app.js`, пункт у `NAV`. Подання повертає `{ title, sub, actions, node, cleanup }`.
- Усі тексти з бази виводяться через `textContent` (допоміжна функція `h()`), тому XSS через вміст бази неможливий.
- Інлайн-стилі заборонені політикою CSP: використовуйте класи й CSS-змінні.
- Шрифти: Lora, Carlito, DejaVu Sans Mono (підмножини Latin і Cyrillic у `web/fonts`, ліцензії в `LICENSES.txt`).
