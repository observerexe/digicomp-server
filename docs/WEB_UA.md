# Вебзастосунок DigiComp HUB

Фронт (React + TypeScript + Vite, PWA) лежить у `web/`. Збірку `web/dist` роздає той самий NestJS з того самого домену:
- сторінки застосунку — на будь-якій адресі (`/`, `/tasks`, `/lab/CNC-1`...);
- API — лише під `/api`;
- `/health` — у корені.

Тому cookie-вхід, CSRF і CSP працюють без CORS.

## Команди

    cd web
    npm ci
    npm run dev          # http://localhost:5173, запити /api проксуються на API :3000
    npm test             # Vitest + Testing Library
    npm run lint         # oxlint
    npm run typecheck
    npm run build        # tokens → tsc → vite build → web/dist
    npm run api:types    # типи API з ../api/openapi.json → src/api/schema.d.ts

- **API для `npm run dev`:** запустіть його локально (`cd api && npm run start:dev`) або через `docker compose`.
- **Після зміни API:**
  1. Зберіть API й оновіть схему: `cd api && npm run build && npm run openapi`.
  2. Оновіть типи у фронті: `cd web && npm run api:types`.
  3. Закомітьте обидва файли.

## Як влаштовано

- **`src/api/client.ts`:**
  - типізований клієнт (`openapi-fetch`), завжди шле `X-DC-Client: web`;
  - на 401 один раз оновлює сесію для всіх паралельних запитів;
  - якщо оновити сесію не вдалося, відкривається екран входу.
- **`src/auth/`:**
  - поточний користувач (`/api/auth/me`), вхід, другий крок 2FA (код або запасний код), вихід;
  - права в інтерфейсі беруться з `permissions`, але остаточно їх перевіряє сервер.
  - Смужка «Працюєте на … з 10:02 · Завершити» показується над вмістом на всіх екранах, поки триває мій сеанс (оновлюється щохвилини).
  - `logout({ notice, next })` не перенаправляє сам: екран входу відкриває `RequireAuth`. `notice` пояснює там, чому сесія закінчилась (змінено пароль, увімкнено 2FA), а `next` вказує, куди повернутися після входу. Так кінцева адреса не залежить від того, в якому порядку оновлюються стан і маршрут.
- **Типи відповідей** беруться з OpenAPI (`src/api/types.ts` перейменовує схеми з `schema.d.ts`). Схеми відповідей додаються в бекенді разом із кожним розділом.
- **`src/errors/messages.ts`:** людський текст для кожного `errorCode`. Тест `messages.test.ts` збирає коди з бекенду й падає, якщо для якогось коду немає тексту.
- **`src/layout/`:**
  - на телефоні — нижня панель (Головна, ТЗ, «Скан QR», Лабораторія, Профіль) і меню «Ще»;
  - на комп'ютері (від 900 px) — бічне меню;
  - розділ «Керування» бачать лише модератори й адмін.
- **Стилі:**
  - CSS-модулі й CSS-змінні;
  - `src/styles/tokens.css` генерується з [`docs/design/tokens.json`](design/tokens.json) (`npm run tokens`), руками не редагується.
- **Теми:** системна, світла або темна, вибір зберігається на пристрої. Із системним «менше руху» анімації вимкнено.
- **Шрифт:** e-Ukraine (WOFF2) у `public/fonts/` разом з `LICENSE.txt` (CC BY 4.0, атрибуція — на сторінці «Про застосунок»).
- **PWA:**
  - маніфест, іконки й service worker (`vite-plugin-pwa`);
  - service worker кешує лише оболонку застосунку. Відповіді API не кешуються ніколи: вони особисті й мають бути свіжими.

## Розділи

| Адреса | Що там |
|---|---|
| `/team` | Команда: картки учасників, пошук за ім'ям, посадою чи спеціальністю, фільтр за спеціальністю. Група невелика, тож список вантажиться одним запитом (до 100 людей), а пошук і фільтр працюють на пристрої миттєво. |
| `/team/:id` | Чужий профіль: лише публічне (аватар, ім'я, посада, спеціальність, біо, бали). Свій id веде в `/profile`. |
| `/profile` | Мій профіль: біо, баланс і місце в рейтингу, історія балів (зняте нарахування — один закреслений рядок із причиною), попередження й штрафи, мої ТЗ, проєкти, допуски, бронювання, 2FA, вихід. |
| `/profile/edit` | Біо й аватар. Поля імені, посади, спеціальності доступні за правами (`profile.edit_own_name`, `profile.edit_own_role_info`). Фото перед завантаженням зменшується на пристрої до 512 px (JPEG), бо ліміт сервера 2 МБ. |
| `/profile/password` | Зміна пароля. Сервер закриває всі сесії, тож застосунок виходить і просить увійти з новим паролем. |
| `/profile/2fa` | Увімкнення 2FA: QR-код (малюється на пристрої в SVG, секрет нікуди не йде), ключ для ручного введення, код, 8 запасних кодів (скопіювати або завантажити `.txt`), потім новий вхід. Коли 2FA ввімкнена: нові запасні коди, вимкнення кодом або запасним кодом. |
| `/lab` | Лабораторія: обладнання зі станом (вільне, зайняте ким, на обслуговуванні) і позначкою допуску, пошук і фільтр за категорією. |
| `/lab/:code` | Сторінка обладнання (id або QR-код). Почати й завершити роботу (галочка про техніку безпеки, ключ ідемпотентності на кожну спробу, час ставить сервер). Попередження про бронювання: чужий поточний слот блокує старт (крім admin), про пізніше сьогодні сказано, до котрої можна працювати. Бронювання: тиждень, вільні проміжки з 08:00 до 22:00, форма в київському часі, скасування. Несправності з фото (до 3, зменшуються на пристрої), дії модератора. Останні 10 сеансів (бачать усі), документи обладнання. Модератор завершує чужий сеанс із причиною. |
| `/lab/journal` | Журнал: модератор фільтрує за періодом, обладнанням і особою, вивантажує CSV і сторінку для друку (серверні `/api/work-sessions/export.csv` і `/report` звичайними посиланнями). Учасник бачить лише свої сеанси. |
| `/lab/stickers` | Наліпки QR для друку (A4, 6 × 6 см), лише `places.manage`. У QR повна адреса `https://…/lab/<код>`, тож звичайна камера телефона відкриває сторінку одразу. |
| `/scan` | Сканер: камера й рамка. Розпізнає вбудований `BarcodeDetector`, а де його немає (iPhone, Firefox) — `jsQR`, який вантажиться окремим файлом лише тоді. Є ручне введення коду. Приймаються лише адреси цього ж застосунку або просто код, посилання на інші сайти ігноруються. |
| `/tasks` | Дошка ТЗ: Вільне, В черзі, В роботі, На перевірці, Виконано; «Усі / Мої». На телефоні колонки — вкладки, дії — кнопками на картках. На комп'ютері колонки поруч і картки можна перетягувати мишею, але лише в дозволені для ролі переходи (`dropAction` у `pages/tasks/logic.ts`). «Повернути» завжди просить коментар. Дія миттєво переносить картку, а якщо сервер відмовив, дошка повертається і показує текст за кодом. З виконаних вантажаться останні 30, далі «Показати ще». |
| `/tasks/:id` | Картка ТЗ: бали й поділ між виконавцями (як на сервері: остача тим, хто взяв раніше), дедлайн, виконавці в порядку взяття, дії включно з «Відмовитися», коментарі (повернення виділено), файли до 20 МБ. Модератор редагує, а вільне ТЗ без виконавців видаляє після підтвердження. |
| `/tasks/new`, `/tasks/:id/edit` | Форма ТЗ (`tasks.create` / `tasks.manage`): назва, опис, бали 0–1000, виконавців 1–20, дедлайн — кінець вибраного дня за Києвом. |
| `/projects` | Дошка проєктів за етапами (Ідея → Завершено), «Усі / Мої». Спільний компонент `components/Board.tsx` з дошкою ТЗ: на телефоні вкладки, на комп'ютері перетягування мишею — лише для тих, хто може редагувати проєкт (модератори або учасники проєкту). Етап змінюється миттєво і повертається, якщо сервер відмовив. |
| `/projects/:id` | Проєкт: дати, етап і прогрес (змінюються на місці, якщо `canEdit`), опис, досягнення, джерела (http/https стають посиланнями), учасники, файли, історія змін з аудиту. Модератор переносить в архів після підтвердження. |
| `/projects/new`, `/projects/:id/edit` | Форма проєкту. Склад учасників (`memberIds`) змінюють лише модератори; учасник проєкту редагує решту полів. Дедлайн не раніше початку. |
| `/rating` | Рейтинг «за місяць / за весь час»: топ-3 на п'єдесталі, далі таблиця; однакова сума — однакове місце; мій рядок підсвічено, моє місце закріплено внизу екрана. |
| `/points` | Бали (`points.award`): нарахування за побутові задачі (модератор не бачить себе у списку) та історія учасника; ручне нарахування знімається з причиною: модератор — своє, адмін — будь-яке. |
| `/discipline` | Дисципліна (`discipline.issue`): видати попередження, штраф (з сумою) чи догану; таблиця з фільтрами за учасником і станом; зняття з причиною: модератор — своє, адмін — будь-яке. У чужому профілі модератор має кнопки сюди з уже вибраною людиною. |

## Вхід через cookie

- **`POST /api/auth/login` із заголовком `X-DC-Client: web`:**
  - ставить два HttpOnly-cookie: `dc_at` на 1 годину і `dc_rt` на 30 днів (шлях `/api/auth`);
  - тіло відповіді містить лише `user`: токени ніколи не потрапляють у JavaScript;
  - якщо в людини увімкнена 2FA, відповідь — `{ twoFactorRequired, challengeToken }`, а cookie ставить `POST /api/auth/2fa/verify`.
- **`/api/auth/refresh` і `/api/auth/logout`** беруть refresh-токен із cookie.
- **Звичайні API-клієнти** (curl, скрипти) працюють як раніше: токени в тілі відповіді й заголовок `Authorization: Bearer`.

## Захист від підробки запитів (CSRF)

- Cookie мають `SameSite=Strict`.
- Усі запити, що змінюють дані за cookie-входу, мусять нести заголовок `X-DC-Client: web`. Заголовок `Origin`, якщо він є, має збігатися з адресою сервера (`Host` або `X-Forwarded-Host`). Інакше 403 із кодом `CSRF`.
- Запити з `Authorization: Bearer` і без cookie ця перевірка не зачіпає.

## Заголовки безпеки й кешування

- **CSP на кожній відповіді, сторінки застосунку теж:**
  - заборонені вбудовані скрипти й стилі та зовнішні ресурси, все вантажиться з власного домену;
  - збірка Vite не містить вбудованих скриптів, тому CSP послаблювати не потрібно.
- **Інші заголовки:** `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `Permissions-Policy` (камеру дозволено лише власному сайту, для сканування QR).
- **Кешування:**

  | Що | `Cache-Control` |
  | --- | --- |
  | API | `no-store` |
  | `index.html`, service worker, маніфест | `no-cache` (оновлення приходять одразу) |
  | файли з хешем у `/assets/` | кешуються назавжди |
  | шрифти й іконки | тиждень |

- **Код:** `api/src/common/web.ts` і `api/src/web/serve-web.ts`, підключення в `api/src/setup-app.ts`.

## Змінні в `.env`

    COOKIE_SECURE=true
    PUBLIC_ORIGIN=https://digicomp.tailfbb38b.ts.net

- `COOKIE_SECURE=true` додає прапорець Secure до cookie. Потрібно, коли сайт відкривають через https; локально — `false`.
- `PUBLIC_ORIGIN` — адреса, яка потрапляє в QR-коди. Фронт отримує її з `GET /api/app-config`.
- `WEB_DIST` — тека зібраного фронту. У Docker це `/app/web`, локально за замовчуванням `../web/dist`. Якщо збірки немає, API працює сам, без сторінок.

## Збірка образу

`api/Dockerfile` збирає фронт і API в один образ, контекст збірки — корінь репо (`docker-compose.yml`). Тож `docker compose up -d --build` оновлює все разом.

## Відомі питання

`npm audit` повідомляє про вразливість середнього рівня в `deepmerge`/`glob` через `workbox-build`. Цей пакет працює лише під час збірки й генерує service worker, у браузер він не потрапляє. Оновимо, щойно `vite-plugin-pwa` вийде з виправленням.
