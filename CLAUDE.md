# DigiComp HUB

Вебзастосунок творчої групи: команда, обладнання з QR і журналом роботи, архів документів,
розумна лабораторія (Home Assistant), склад, проєкти, ТЗ, бали, дисципліна, панелі керування.
Повні вимоги, матриця прав і план етапів: `docs/PLAN.md`. Перед будь-якою задачею читай його.

## Мова
- Спілкування з власником, коментарі в документації, тексти інтерфейсу — українською.
- Код, назви змінних, коміти — англійською.

## Структура
- `api/` — бекенд NestJS 12 + TypeORM + PostgreSQL 17 (Docker Compose у корені).
- `api/src/<модуль>/` — controller, service, entity, dto для кожного модуля.
- `api/src/migrations/` — міграції бази. `synchronize` вимкнено, схема змінюється лише міграціями.
- `docs/*_UA.md` — довідники: API, вебчастина, бекапи, міграції, Home Assistant, розширена панель.
- `ops/agent/` — агент на сервері для розширеної панелі (Python, systemd).
- `web/` — фронт: React + TypeScript + Vite, PWA. Його роздає NestJS; API — під `/api`. Довідник: `docs/WEB_UA.md`.
- `docs/design/` — затверджений дизайн: `tokens.json` (кольори, шрифт, розміри) і правила.

## Команди
- Запуск усього: `docker compose up -d --build`
- Бекенд локально: `cd api && npm ci && npm run start:dev`
- Тести: `cd api && npm test` і `npm run test:e2e`; агент сервера: `python3 -m unittest discover -s ops/agent`
- Лінтер: `cd api && npm run lint`
- Фронт: `cd web && npm test && npm run lint && npm run typecheck && npm run build`
- Після зміни API: `cd api && npm run build && npm run openapi`, потім `cd web && npm run api:types`
- Нова міграція: `./scripts/migration-generate.sh <Name>`

## Правила роботи
- Працюємо етапами з `docs/PLAN.md`, по одному етапу за сесію, кожен етап в окремій гілці.
- Спершу план, код лише після підтвердження власника.
- Після змін: тести й лінтер мають бути зеленими. Познач виконані пункти чек-листа в `docs/PLAN.md`.
- Будь-яка зміна API — оновити `docs/API_UA.md` (і OpenAPI, коли він з'явиться).
- Не змінювати схему бази без міграції. Міграція не повинна втрачати наявні дані.
- Не ламати безпеку, що вже є: cookie-вхід з CSRF, CSP, ліміти запитів, аудит, список дозволених пристроїв HA.
  Розетки й вимикачі HA (`switch.*`) не додавати.
- Перевірки прав — в одному місці, за матрицею з `docs/PLAN.md`. На кожне правило — тест.
- Кожна дія модератора чи адміна над іншим користувачем пишеться в аудит.
- Помилки API повертають стабільний `errorCode`; фронт показує текст за кодом.

## Ролі (коротко)
- `admin` — усе, включно з розширеною панеллю. Єдиний, хто скидає паролі й змінює ім'я іншого.
- `moderator` — керує ТЗ, проєктами, балами, дисципліною, обладнанням, складом, документами;
  не чіпає ім'я, біо й аватар інших, не діє над іншими модераторами й адміном,
  не нараховує бали собі й не приймає власне ТЗ.
- `member` — бере ТЗ, працює з обладнанням за допуском, бере й поповнює склад, редагує своє біо й аватар.

## Сервер
- Ubuntu Server, Docker Compose, доступ ззовні через Tailscale Funnel. HA на тому ж сервері (`network_mode: host`).
- Доступ до сервера: `ssh digicomp@digicomp` (дозвіл власника від 2026-11-09). Межі:
  читати (статус, логи, вивід команд) можна без питань; кожну команду, що щось змінює
  (бекап, `git pull`, `docker compose up`, відкат), спершу назвати і дочекатися «так» власника;
  `sudo` не використовувати — агента панелі й `tailscale serve` власник ставить сам.
- Порядок розгортання:
  бекап → `git pull` → `docker compose up -d --build` → перевірка `/health`.
